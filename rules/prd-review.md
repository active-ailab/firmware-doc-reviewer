# 通用 PRD Review 规则

本规则以产品经理视角评估 PRD 是否让研发能够理解需求、完成初步拆分与估算，并形成可验收的交付闭环。评审不要求代码、协议字段、架构选型或具体实现方案。

## 1. 输入与证据

最小输入：

1. PRD 链接或正文；
2. PRD 明确写出的目标用户、业务场景、范围和版本边界；
3. 涉及的产品端、系统、团队或外部合作方（如已知）。

可选证据包括交互稿、内容/多语言资源、数据口径、依赖说明、合规要求、发布计划、埋点定义、历史需求和验收材料。

- 先阅读 PRD 及其明确关联、且理解当前需求所必需的资料；关联资料继续引用必要资料时，继续阅读直到能判断需求边界、研发拆分、交付或验收。
- 以已访问的资料为证据，不把推断写成事实；无法访问的资料必须记录缺口和影响。
- 关联资料缺失仅在实质阻断产品决策、研发拆分、交付或验收时设为 Block；否则作为待确认项。
- 不要求每份 PRD 均包含业务 KPI。执行、适配、合规或项目依赖类需求，可用问题来源、外部要求、覆盖范围或完成条件说明需求价值；缺少独立 KPI 不扣分，也不单独构成 Block。

## 2. 评审顺序

1. 提取需求价值与决策依据、目标用户、场景、范围、优先级和版本边界。
2. 拆分用户主流程、功能规则、异常分支、交互和内容输入，识别相互矛盾或无法执行的描述。
3. 识别受影响的端、系统、数据、外部合作方和责任边界，判断研发能否据此初步拆分和估算。
4. 检查适用的性能、隐私、安全、兼容、合规、发布和降级约束，以及已知交付风险。
5. 建立可验证的验收、发布和效果验证条件；只有需求类型适用时才要求效果指标。
6. 选择适用评分维度、记录证据和改进动作，识别 Block 并按固定模板输出。

## 3. 研发评审边界

通用 PRD Review 评估产品层的研发影响：

- 是新增、调整还是复用既有能力；
- 影响哪些端、系统、数据、资源或角色；
- 是否存在跨端协同、外部依赖、数据迁移、发布、兼容或合规约束；
- 是否能形成初步责任拆分、工作量估算和验收范围。

不评估或要求以下实现细节：模块路径、代码设计、接口字段、协议报文、数据库表结构、架构选型、性能优化方案。代码仓库不是默认输入；只有用户明确要求核对既有能力，或“复用/无影响”结论存在实质争议时，才在报告外完成独立的实现可行性确认。

## 4. 评分与 Block

总分 100 分。只列出适用维度；明确不适用的维度直接跳过，按适用维度权重折算为 100 分。适用但证据不足时，按其对产品决策、拆分、交付或验收的实际影响扣分。

| 维度 | 满分 | 评审重点 |
|---|---:|---|
| 需求价值与决策依据 | 5 | 问题来源、需求价值、优先级依据或外部完成条件是否明确。 |
| 目标用户与使用场景 | 10 | 目标用户、使用前提、主场景和关键边界是否明确。 |
| 范围、优先级与版本边界 | 15 | 首发范围、非目标、优先级、版本或分阶段边界是否可执行。 |
| 功能规则与端到端流程 | 15 | 主流程、关键规则、异常、状态转换和端到端结果是否一致。 |
| 交互、内容与产品输入 | 10 | 页面/交互、文案、资源和设计输入是否足以支持交付。 |
| 研发影响与可行性边界 | 20 | 影响端、复用/新增边界、初步拆分、估算条件和已知限制是否明确。 |
| 数据、依赖与责任边界 | 10 | 数据来源/去向、外部依赖、责任人和协作边界是否明确。 |
| 非功能约束与交付风险 | 10 | 适用的性能、隐私、安全、兼容、合规、降级和发布风险是否可处理。 |
| 验收标准、发布与效果验证 | 5 | 功能验收、发布条件和适用的效果验证是否可判断。 |

判定规则：

- 通过：总分不低于 80 且 Block 为 0。
- 有条件通过：总分 60–79 且 Block 为 0；可进入下一阶段，但必须关闭报告中的必补项。
- 不通过：总分低于 60，或存在任意 Block。

Block 仅用于以下会阻断产品决策、研发拆分、交付或验收的缺口：核心目标、范围或主流程相互矛盾；关键依赖没有责任人或完成路径；已知合规、兼容或安全风险没有处理原则；或没有可判断的验收标准。缺少技术实现细节、独立业务 KPI、具体版本号、设计稿或资源本身不得单独构成 Block，除非其已实质阻断上述事项。

分数表示 PRD 信息完整度和交付风险可控度，不表示需求优先级或研发工期。

## 5. 输出契约

报告严格只输出以下第一部分及三个固定二级标题；不得输出 `## 2. 详细信息`、附录或其他章节。不适用维度不列入评分表；适用但无问题时写“已确认，无阻塞项”，不输出“无”占位行。

## 6. 关键检查清单

### 6.1 需求与流程

- 需求价值、问题来源、优先级依据或外部完成条件是否明确？
- 目标用户、主场景、非目标和范围边界是否明确？
- 主流程、异常/中断/恢复、关键状态和规则是否前后一致？

### 6.2 研发影响与依赖

- 新增、调整和复用的产品能力边界是否明确？
- 受影响的端、系统、数据、资源和责任方是否能识别？
- 是否存在跨团队、第三方、迁移、兼容、发布或合规依赖，且有完成路径？
- 研发是否可以据此初步拆分工作、估算范围并识别风险？

### 6.3 交付与验收

- 交互、内容、设计和资源输入在需求适用时是否可交付？
- 适用的性能、隐私、安全、兼容、合规和降级要求是否明确？
- 验收对象、操作、预期结果、发布条件和必要证据是否可判断？
- 增长、运营、算法效果类需求是否定义效果验证；其他需求是否有可替代的完成条件？
